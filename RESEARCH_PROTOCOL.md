# ECHO — научная работа и исследование удобства (план, без вымышленных результатов)

## 1. Название и проблема

**ECHO: бесплатный офлайн-коммуникатор дополнительной и альтернативной коммуникации для людей с затруднениями речи.**

Проблема для исследования: насколько быстро и безошибочно новый пользователь может передать повседневную просьбу с помощью интерфейса ECHO? Доступность необходимо оценивать с учётом сенсорных и моторных особенностей пользователей, а не только визуального дизайна.

## 2. Цель, задачи и гипотеза

**Цель:** разработать и оценить понятный AAC-интерфейс для выбора, составления и озвучивания коротких повседневных фраз без обязательного подключения к интернету.

**Задачи:** собрать требования; изучить общие решения AAC; разработать интерфейс и офлайн-функции; провести добровольное тестирование; измерить скорость и успешность выполнения задач; изучить проблемы доступности; исправить обнаруженные ошибки.

**Проверяемая гипотеза:** при одинаковых заданиях на одном устройстве упрощённый режим ECHO позволит участникам быстрее найти и озвучить фразу и/или потребует меньше нажатий, чем стандартный режим. Это **предположение**, а не результат.

## 4. Методика исследования

**Тип:** небольшое добровольное сравнительное UX-исследование на **демонстрационных данных**, без реальных личных/медицинских историй и без записи личного голоса участников.

1. До набора участников получить согласование руководителя проекта/учителя. При участии несовершеннолетних — согласие родителя/опекуна и добровольное согласие самого участника, с возможностью остановить участие без объяснения причин.
2. Не привлекать людей с нарушениями речи через давление, ожидание лечения или обещания медицинской пользы. При работе с людьми, которым требуются особые условия доступности, согласовать протокол с компетентным взрослым специалистом и адаптировать задания к человеку.
3. Перед каждым испытанием подготовить одинаковые фразы: «Мне нужна вода», «Мне нужна помощь», «Я хочу домой», а также одну заранее заданную новую фразу. Не использовать реальные экстренные ситуации и **не совершать звонки 112**.
4. Для каждого участника случайным образом чередовать порядок стандартного и упрощённого режимов, чтобы уменьшить эффект обучения.
5. Замерять: **время до успешного произнесения**, **число нажатий**, **процент выполненных задач**, **число ошибок выбора** и добровольную оценку удобства по шкале 1–5. Помечать ошибки, вызванные отсутствием системного голоса, отдельно от ошибок интерфейса.
6. Проверить, какие действия были непонятны, и задокументировать исправления. Проводить повторное испытание только после информирования участников.

## 6. Анализ

- Среднее и медиана времени для каждого режима, разброс и число наблюдений.
- Доля успехов = выполненные задачи / все предпринятые задачи × 100%.
- Разница времени по участнику при парном дизайне: T(обычный) − T(простой). Для небольших выборок честно показывать индивидуальные точки, медианы и неопределённость.
- По возможности — доверительные интервалы, описать размер выборки и ограничения.
- Разделить результаты автоматических тестов кода и пользовательские результаты. Сборка APK и 100% прохождение автотестов **не доказывают** удобство для людей с ограничениями речи.

## 7. Этика и приватность

Не публиковать в GitHub необработанные ответы, фотографии, голосовые образцы и личные медицинские сведения участников. Хранить только минимальные обезличенные метрики с разрешения участников и взрослых руководителей. Не пытаться делать выводы о состоянии здоровья человека по его скорости нажатий.

## 9. План презентации и видео

**10 слайдов:** название; проблема; для кого проект; цель/гипотеза; сравнение; функции и офлайн; дизайн/доступность; метод исследования; реальные графики (когда будут); вывод и дальнейшая работа.

**Видео (60–90 с):** показать домашний экран, выбрать карточку, озвучить фразу, создать карточку, переключиться в простой режим, продемонстрировать офлайн-сценарий и резервное копирование на **вымышленных данных**. Не демонстрировать личные записи без согласия.

**Статус:** шаблон и протокол подготовлены; исследование, согласия, измерения, графики и видеозапись **не выполнены**.
