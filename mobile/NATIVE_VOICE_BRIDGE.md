# ECHO — контракт нативного мобильного ИИ-голоса (Android / iOS)

Этот документ описывает **реальный JavaScript-интерфейс, подключённый в `features.js`**, но не утверждает, что бинарный движок или нативные приложения уже существуют.

## Интерфейс оболочки

Нативная оболочка Android / iOS должна создать `window.echoNativeVoice` **до загрузки `features.js`** в доверенном, упакованном HTML-приложении:

```typescript
interface EchoNativeVoice {
  status(): Promise<{
    platform: "android" | "ios";
    ready: boolean;
    languages: string[]; // только реально проверенные, напр. ["en"]
  }>;
  synthesize(args: {
    text: string;
    language: string;
    referenceWavBase64: string; // собственный голос, локально из IndexedDB
    signal: AbortSignal;        // отмена на стороне JS, оболочка должна отменять inference
  }): Promise<Blob | { wavBase64: string }>;
}
```

### Правила безопасности
- Оболочка **не должна** инжектировать `echoNativeVoice` в произвольные сайты или внешние WebView.
- Протокол следует реализовывать через платформенные изолированные сообщения, а не открытый HTTP-порт или URL-схему.
- Проверять `text` (непустой, длина до 300), `language` (поддерживаемый язык), размер/тип аудио; ограничить время и частоту запросов.
- Проверка `status().ready` в JavaScript — UX-проверка, **не граница безопасности**: нативный код должен сам проверять наличие локальной модели, источник сообщения и согласие на использование образца.
- Голосовой образец не передавать в интернет и не логировать; хранить в приватном каталоге приложения, предусмотреть удаление.
- Модель скачивать однократно с проверкой контрольной суммы и лицензии; затем **полностью офлайн**.
- `synthesize` должен вернуть **настоящий ненулевой WAV RIFF/WAVE**. Браузер проверяет заголовок и сохраняет его в IndexedDB; до мобильного теста качество не подтверждено.
- Кнопка «Остановить» отменяет ожидание в JS. Сам нативный движок должен отдельно реализовать реальную отмену и очистку памяти.

### Порядок разработки

1. Собрать Android-оболочку, упаковать локальный web UI и встроить проверенный sherpa-onnx/PocketTTS inference. Одна лишь WebView без двигателя **не выполняет** цель.
2. Добавить безопасный асинхронный JS bridge на Android и перехват `status()/synthesize()`; проверить на физическом телефоне в авиарежиме.
3. Создать iOS-оболочку с `WKWebView`, ограниченным `WKScriptMessageHandler`/reply API, нативной моделью и тем же интерфейсом.
4. Протестировать генерацию неизвестной ранее английской фразы и добровольное сравнение со своим голосом. Отдельно измерить память, температуру и задержку.

**Текущий статус:** JS-side интеграция реализована; Android/iOS binary engines, нативные оболочки и реальная мобильная генерация **ещё не сделаны**. GitHub Pages **не выполняет** персональную генерацию на телефоне.
