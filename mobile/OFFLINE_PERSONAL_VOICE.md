# ECHO — автономный персональный голос на телефоне

## Цель (критерии приёмки)

Установленное на телефоне ECHO должно произносить **новый** текст с опорой на **собственный** голосовой образец, в авиарежиме, без Python, ПК, внешнего сервера и обязательной подписки.

На 2026-11-07 этот функционал **не реализован в ECHO**. Веб-PWA содержит записи, системный TTS и localhost-only Chatterbox. Никакая кнопка PWA не должна заявлять, будто мобильное клонирование голоса готово.

## Подтверждённый кандидат: Pocket TTS на sherpa-onnx

Официальные документы sherpa-onnx подтверждают PocketTTS zero-shot voice cloning по reference audio:
- https://k2-fsa.github.io/sherpa/onnx/tts/pocket.html
- C++ / Java-Kotlin / Swift примеры приведены в официальной документации.
- Архив модели: `sherpa-onnx-pocket-tts-int8-2026-01-26.tar.bz2` на GitHub Releases k2-fsa/sherpa-onnx.
- PocketTTS не требует транскрипта голосового образца; это не означает, что поддерживаются все языки.

Проверяемые цели: сначала **Android, английский язык**, затем iOS. Русский, казахский, белорусский нельзя объявлять поддержанными без тестов. Лицензии отдельно проверяются для приложения, sherpa-onnx, модели и зависимостей перед распространением.

## Архитектура реализации

1. Нативная Android оболочка (Kotlin), встраивающая локальный web-интерфейс ECHO **без передачи пользовательских данных по сети**. Для iOS требуется отдельная оболочка и сборка.
2. Нативный модуль PocketTTS/sherpa-onnx запускает inference прямо на устройстве и остаётся недоступен из внешних сайтов.
3. Пользователь добровольно записывает собственный WAV, прослушивает, даёт согласие, сохраняет только в приватном хранилище приложения.
4. Модели загружаются **один раз** с проверкой SHA-256 и лицензии; после этого все операции синтеза работают с выключенной сетью. До установки модели голосовой режим явно указывает «модель не установлена».
5. Мобильный bridge строго валидирует локальный запрос `{text, language, reference_id}` и возвращает локальный WAV; ни текст, ни образец голоса не передаются на облачные API.
6. Статусы: `unavailable`, `model_not_installed`, `ready`, `generating`, `error`. Только `ready` может разрешать нативную генерацию.
7. При сбое остаются доступными существующие записи, системный TTS, карточки и SOS. Не имитировать генерацию проигрыванием заранее записанного образца.
8. Для iOS — нативный sherpa-onnx/Swift либо проверенный WASM-движок; Android APK не является iOS решением.

## Минимальная сквозная проверка перед заявлением «готово»

- Установить сборку на **реальный Android**, загрузить модель, перейти в авиарежим и перезапустить приложение.
- Записать свой голос с явным согласием. Ввести новый английский текст, которого не было в образце.
- Сгенерировать WAV на телефоне; убедиться, что он ненулевой, воспроизводится и соответствует новому тексту. Проверить похожесть слепым прослушиванием добровольных участников.
- Повторить после закрытия приложения; проверить отсутствие сетевых запросов во время синтеза, удаление образца и результата, отказ без согласия.
- Отдельно провести тест памяти/температуры/задержки на слабом Android и тест iPhone.
- Разделить «модель сгенерировала звук» и «голос похож на владельца» — это разные проверки.

## Быстрый внешний Android proof of concept (НЕ интеграция ECHO)

Проект https://github.com/HayaiApp/HayaiTTS заявляет автономные Pocket/ZipVoice reference-audio функции в собственной Android-студии и системный TTS-движок. Можно протестировать возможности конкретного телефона с **собственным** голосом после проверки релиза и источника приложения. **Это другая программа, а не готовый ECHO**. Совместимость браузерного speechSynthesis с её системным голосом необходимо подтвердить отдельно; не обещать, что клон автоматически появится в ECHO.

## Ограничения

GitHub Pages не запускает Python/Chatterbox. Нельзя размещать приватный аудиообразец в публичном репозитории, отправлять его на внешний сервер без отдельного разрешения или заявлять офлайн-клонирование без работающего мобильного рантайма.

**Статус:** архитектура и критерии, не мобильная реализация.
